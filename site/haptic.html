햅틱

진동 피드백을 언제·얼마나 쓸지에 대한 기준입니다. 아직 정의되지 않았습니다 — 이 페이지는 무엇을 정해야 하는지를 담고 있습니다.

Figma에 햅틱 페이지가 아직 없습니다. 원본(2026-07-30 기준 62페이지)을 전수 조회했지만 haptic·햅틱·진동 관련 정의가 확인되지 않았습니다. 따라서 아래 내용은 측정값이 아니라 정해야 할 항목의 목록입니다.

패턴 테스트

패턴은 느껴보고 정해야 합니다. 아래는 논의를 시작하기 위한 후보이며 확정된 GDS 값이 아닙니다.

기기 확인 중…

진동은 안드로이드 크롬에서만 울립니다. 데스크톱은 진동 장치가 없고, iOS Safari는 웹 진동 API를 지원하지 않습니다 — 브라우저 제약이라 우회할 수 없습니다. 그래서 「소리로 듣기」를 같이 넣었습니다. 저주파 버즈로 같은 리듬을 재생하므로 어느 기기에서든 패턴의 길이와 간격은 비교할 수 있습니다. 재생 중에는 파형도 함께 움직입니다.

웹 테스트의 한계 — 브라우저는 지속시간만 제어합니다. 네이티브가 쓰는 강도(intensity)와 질감(sharpness)은 표현되지 않습니다. 여기서 정할 수 있는 건 리듬까지이고, 실제 감촉은 앱 빌드에서 다시 확인해야 합니다.

정해야 할 것

  • 패턴 정의 어떤 종류의 피드백을 몇 개로 나눌지. 선택 / 성공 / 경고 / 오류 / 임팩트 강약 등
  • 사용 시점 어떤 인터랙션에 붙일지. 예약 완료 · 스마트키 잠금·해제 · 결제 · 오류 등 GDS 컴포넌트와의 대응
  • 플랫폼 매핑 같은 패턴을 iOS와 Android에서 각각 무엇으로 구현할지. 두 OS의 API 체계가 다릅니다
  • 강도 · 지속시간 단계별 수치. 이게 정해져야 토큰으로 내보낼 수 있습니다
  • 접근성 · 사용자 설정 시스템 햅틱을 끈 사용자, 저전력 모드, 운전 중 상황을 어떻게 다룰지
  • 남용 방지 기준 연속 진동 제한, 스크롤·리스트처럼 반복되는 동작에서의 금지 규칙

플랫폼 API — 참고

패턴을 정의할 때 각 OS가 제공하는 기본 단위를 알고 있어야 합니다. 아래는 GDS 결정이 아니라 OS가 제공하는 것입니다.

구분iOSAndroid
선택 변경UISelectionFeedbackGenerator HapticFeedbackConstants.CLOCK_TICK
결과 알림UINotificationFeedbackGenerator
success / warning / error		 HapticFeedbackConstants.CONFIRM / REJECT
충격 강도UIImpactFeedbackGenerator
light / medium / heavy / soft / rigid		 VibrationEffect.createPredefined
Composition (강도 지정 가능)
사용자 정의Core Haptics (.ahap) VibrationEffect.createWaveform

두 OS의 단계 구분이 1:1로 맞지 않습니다. GDS 패턴을 먼저 정하고 각 OS 값을 매핑하는 순서여야 하며, 반대로 하면 한쪽에 종속됩니다.

토큰으로 나가는 형태 미정

패턴과 수치가 정해지면 다른 Foundation 축과 같은 방식으로 내보냅니다.
